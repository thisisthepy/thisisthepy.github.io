pythonx-concurrent

Structured concurrency for Python on Kotlin Multiplatform: coroutines that interoperate with Kotlin coroutines and asyncio.Kotlin Multiplatform 위 Python의 구조적 동시성: Kotlin 코루틴, asyncio와 함께 도는 코루틴.

GitHub · Spec

The idea

On Android, work runs in Kotlin coroutines; in Python, it runs in asyncio. An app written in Python on Kotlin Multiplatform lives in both worlds. pythonx-concurrent gives it one model with Kotlin's vocabulary in Python's spelling: a Scope used with async with, launch and defer, with_context(Dispatchers.IO, ...), timeouts and supervision, and cancellation that crosses the language boundary in both directions.

async with Scope() as s:
    profile = s.defer(fetch_profile, user_id)
    s.launch(log_visit, user_id)
    data = await with_context(Dispatchers.IO, read_cache, user_id)

The innovative part

  • Goroutine-style scheduling of many lightweight tasks over a few carrier threads, parallel on free-threaded CPython.
  • Python on Kotlin's threads. In Kotlin mode a Python coroutine is stepped by a Kotlin coroutine, one send() at a time, on any Kotlin dispatcher. Between steps it holds no GIL and no native frame, so it can live on JVM virtual threads and move between threads, which asyncio tasks cannot.
  • Threads in the browser. With cross-origin isolation by default, the same dispatchers run on worker threads on the web.

Status

Specification written in detail; implementation comes in the pythonx turn. The name is reserved on PyPI.

아이디어

Android에서 작업은 Kotlin 코루틴으로, Python에서는 asyncio로 돕니다. Kotlin Multiplatform 위에서 Python으로 쓴 앱은 두 세계에 동시에 삽니다. pythonx-concurrent는 Kotlin의 어휘를 Python 표기로 쓰는 하나의 모델을 줍니다. async with로 쓰는 Scope, launch와 defer, with_context(Dispatchers.IO, ...), 타임아웃과 감독, 그리고 언어 경계를 양방향으로 넘는 취소입니다.

async with Scope() as s:
    profile = s.defer(fetch_profile, user_id)
    s.launch(log_visit, user_id)
    data = await with_context(Dispatchers.IO, read_cache, user_id)

새로운 부분

  • 고루틴 방식의 스케줄링. 가벼운 작업 여러 개를 몇 개의 캐리어 스레드에 얹고, free-threaded CPython에서는 병렬로 돌립니다.
  • Kotlin 스레드 위의 Python. Kotlin 모드에서는 Kotlin 코루틴이 Python 코루틴을 send() 한 번씩, 어떤 Kotlin 디스패처에서든 실행합니다. 단계 사이에는 GIL도 네이티브 프레임도 쥐지 않아서 JVM 가상 스레드 위에서 살 수 있고, asyncio 태스크와 달리 스레드 사이를 옮겨 다닐 수 있습니다.
  • 브라우저의 스레드. 교차 출처 격리가 기본이라 같은 디스패처가 웹의 워커 스레드에서도 돕니다.
