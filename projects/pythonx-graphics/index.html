pythonx-graphics

Declarative 2D and 3D graphics for Python: Compose for 2D, Filament for 3D, and scenes built for AI agents.Python을 위한 선언형 2D·3D 그래픽스: 2D는 Compose, 3D는 Filament, 그리고 AI 에이전트를 위한 장면.

GitHub · Spec

The idea

A replacement for three.js, for Python apps on every platform, with one model for 2D and 3D. A 3D scene is a Compose composition whose nodes are entities of Filament, Google's physically based renderer for Vulkan, Metal and OpenGL. Python declares cameras, lights, models and behaviours the way it declares UI, and Compose HUDs sit over 3D views, driven by the same state.

Scene3D(camera=Camera(position=(0, 1.5, 4), look_at=(0, 0, 0)), content=lambda: {
    Sun(intensity=100_000, direction=(-1, -1, -1)),
    Model("models/chair.glb", name="chair", behaviours=[Spin(axis=(0, 1, 0), speed=30)]),
})

Two design ideas

Motion is declared, so Python stays off the frame loop

Tweens, springs, paths, physics and constraints are data that the native side runs every frame. Python runs on events. Per-frame logic that must be Python is compiled by TypedPython and parallelised on free-threaded CPython. Ten thousand instances come from one array, with no Python object per instance.

Every scene is a document an agent can work on

  • A typed scene representation with stable ids, round-tripping to the Python declaration.
  • Descriptions and queries for language models, with spatial relations computed from bounds.
  • Grounding in pixels through an entity-id buffer and depth, so "the red chair" in an image becomes a node.
  • Edits as transactions: validated against schemas and app-defined constraints, previewed, undoable, and emitted as source patches that can be reviewed and committed.
  • Tool schemas generated from the components; headless, deterministic rendering; recording and replay.

Status

Specification written; implementation comes in the pythonx turn. The name is reserved on PyPI.

아이디어

모든 플랫폼의 Python 앱을 위한 three.js 대체이고, 2D와 3D가 같은 모델입니다. 3D 장면은 노드가 Filament 엔티티인 Compose 컴포지션입니다. Filament는 Vulkan, Metal, OpenGL을 쓰는 Google의 물리 기반 렌더러입니다. Python은 카메라, 조명, 모델, 행동을 UI처럼 선언하고, Compose HUD가 같은 상태를 보며 3D 화면 위에 겹칩니다.

두 가지 설계

움직임을 선언하니 Python은 프레임 루프에 없다

트윈, 스프링, 경로, 물리, 제약은 네이티브가 매 프레임 실행하는 데이터입니다. Python은 이벤트가 있을 때만 돕니다. 매 프레임 Python이어야 하는 로직은 TypedPython이 컴파일하고 free-threaded CPython에서 병렬로 돌립니다. 인스턴스 1만 개도 배열 하나에서 나오고, 인스턴스마다 Python 객체를 만들지 않습니다.

모든 장면은 에이전트가 다룰 수 있는 문서다

  • 안정적인 ID를 가진 타입 있는 장면 표현이고, Python 선언과 서로 바꿔 쓸 수 있습니다.
  • 언어 모델을 위한 설명과 질의, 경계 상자로 계산한 공간 관계.
  • 엔티티 ID 버퍼와 깊이로 픽셀에 연결해서, 이미지 속 "빨간 의자"가 노드가 됩니다.
  • 트랜잭션으로 수정합니다. 스키마와 앱이 정한 제약으로 검증하고, 미리 보고, 되돌릴 수 있고, 리뷰하고 커밋할 수 있는 소스 패치로 나옵니다.
  • 컴포넌트에서 생성하는 도구 스키마, 창 없는 결정적 렌더링, 기록과 재생.
