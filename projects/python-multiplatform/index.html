python-multiplatform

CPython embedded in Kotlin Multiplatform, with Kotlin and Python calling each other in both directions.Kotlin Multiplatform 안에 CPython을 넣고, Kotlin과 Python이 서로를 양방향으로 부르게 합니다.

GitHub · Guide

What it is

python-multiplatform is the bridge everything else stands on. It embeds an unmodified CPython in a Kotlin Multiplatform app on Android, iOS, desktop and the web, and lets the two languages call each other as if they were one program.

  • Kotlin to Python (downcall). One expect declaration per CPython C API function, about 330 of them, with an actual per platform: JNI registered natives on Android, the Foreign Function and Memory API on desktop, direct calls on Kotlin/Native for iOS. A typed object model sits on top, so Kotlin code works with PyObjects rather than raw pointers.
  • Python to Kotlin (upcall). A function table generated at build time, by a KSP processor for the app's own Kotlin and by an artifact walker that reads the compiled jars and klibs of any library, Compose included. Python enters Kotlin through one entry point per platform.
  • The binder. Kotlin packages appear in Python under their own names: import androidx.compose.material3 is Material 3. Inside a module, every member and keyword is also reachable in snake_case, so fill_max_width() and on_click= work beside fillMaxWidth(). The Gradle plugin writes .pyi stubs for all of it.
  • The Compose host. PythonAppView, PythonWidget and PythonLauncher draw a Python-declared root inside a Compose UI, and rememberSaveableWrapper gives Python Compose's saved state.

Why it is built this way

Kotlin/Native has almost no reflection and a GraalVM native image is a closed world, so nothing may be discovered at run time. Every path from Python into Kotlin is decided while the app builds, and the Kotlin compiler, not a string lookup, chooses the method. The same design that makes native images possible also makes calls fast: the cost of an upcall is measured and tracked, and expensive paths carry an annotation that says so.

The binder never renames a namespace. A Kotlin name in Python means the original Kotlin, which is why pythonx can be a real Python package that builds on top of androidx rather than a disguise for it.

Where it is going

  • Free-threaded only. The embedded interpreter moves to CPython 3.15t with no GIL on every platform, including the browser under cross-origin isolation, using the 3.15 stable ABI for free-threaded builds (abi3t). Python and Kotlin threads then run Python in parallel.
  • Python on Kotlin's threads. A Python coroutine can be stepped by a Kotlin coroutine on any dispatcher, including JVM virtual threads, which is what pythonx-concurrent builds on.
  • Proof by the notebook. pythonx-compose's lecture notebook runs end to end against an installed wheel, 20 scenarios, pixel-equal to the same UI written in Kotlin.

무엇인가

python-multiplatform은 나머지 모든 것이 올라서는 다리입니다. 고치지 않은 CPython을 Android, iOS, 데스크톱, 웹의 Kotlin Multiplatform 앱 안에 넣고, 두 언어가 한 프로그램처럼 서로를 부르게 합니다.

  • Kotlin에서 Python으로 (downcall). CPython C API 함수마다 expect 선언 하나, 약 330개가 있고, 플랫폼마다 actual이 있습니다. Android는 JNI 등록 네이티브, 데스크톱은 Foreign Function and Memory API, iOS는 Kotlin/Native 직접 호출입니다. 그 위에 타입이 있는 객체 모델이 있어서 Kotlin 코드는 포인터가 아니라 PyObject로 일합니다.
  • Python에서 Kotlin으로 (upcall). 빌드 시점에 생성한 함수 표를 씁니다. 앱 자신의 Kotlin은 KSP 프로세서가, Compose를 포함한 모든 라이브러리는 컴파일된 jar와 klib을 읽는 아티팩트 워커가 표를 만듭니다. Python은 플랫폼마다 하나의 진입점으로 Kotlin에 들어갑니다.
  • 바인더. Kotlin 패키지가 원래 이름 그대로 Python에 나타납니다. import androidx.compose.material3는 Material 3입니다. 모듈 안의 멤버와 키워드는 snake_case로도 부를 수 있어서 fillMaxWidth() 옆에서 fill_max_width()와 on_click=이 동작합니다. Gradle 플러그인이 이 모두의 .pyi 스텁을 씁니다.
  • Compose 호스트. PythonAppView, PythonWidget, PythonLauncher가 Python이 선언한 루트를 Compose UI 안에 그리고, rememberSaveableWrapper가 Python에 Compose의 저장 상태를 줍니다.

왜 이렇게 만드는가

Kotlin/Native에는 리플렉션이 거의 없고 GraalVM 네이티브 이미지는 닫힌 세계라서, 실행 중에 무언가를 찾아낼 수 없습니다. 그래서 Python에서 Kotlin으로 가는 모든 경로를 앱이 빌드될 때 정하고, 메서드는 문자열 검색이 아니라 Kotlin 컴파일러가 고릅니다. 네이티브 이미지를 가능하게 하는 이 설계가 호출도 빠르게 만듭니다. upcall 비용은 측정하고 추적하며, 비싼 경로에는 그렇다고 알리는 어노테이션이 붙습니다.

바인더는 네임스페이스 이름을 절대 바꾸지 않습니다. Python에서 보이는 Kotlin 이름은 원래 Kotlin을 뜻합니다. 그래서 pythonx는 androidx를 위장한 것이 아니라 그 위에 쌓은 진짜 Python 패키지가 될 수 있습니다.

어디로 가는가

  • free-threaded 전용. 안에 넣는 인터프리터를 모든 플랫폼에서 GIL 없는 CPython 3.15t로 옮깁니다. 브라우저도 교차 출처 격리 아래에서 같고, free-threaded 빌드용 3.15 안정 ABI(abi3t)를 씁니다. 그러면 Python 스레드와 Kotlin 스레드가 Python을 병렬로 실행합니다.
  • Kotlin 스레드 위의 Python. Python 코루틴을 Kotlin 코루틴이 어떤 디스패처에서든, JVM 가상 스레드에서도 한 단계씩 실행할 수 있습니다. pythonx-concurrent가 이 위에 섭니다.
  • 노트북으로 증명. pythonx-compose의 강의 노트북이 설치된 wheel로 처음부터 끝까지 돕니다. 시나리오 20개가 Kotlin으로 쓴 같은 UI와 픽셀까지 같습니다.
