TypedPython

Ordinary typed Python, checked at build time and compiled ahead of time, with CPython's exact semantics.평범한 타입 붙은 Python을 빌드 시점에 검사하고 미리 컴파일합니다. 의미는 CPython과 정확히 같습니다.

GitHub · Design

What it is

TypedPython lives inside python-multiplatform and does two things. First, a soundness gate in the build: the project's Python is type-checked, and a value whose type leaks to Any is an error, not a warning. Second, opt-in compilation: a typed function is lowered to an intermediate representation, compiled to C, and shipped as an ordinary CPython extension module inside the app.

No new syntax and no new language. A function compiles or it stays in the interpreter, one function at a time.

The promise: same answers, much faster

The compiled code must behave exactly as CPython would. Integers that overflow become big integers instead of wrapping. Index errors raise the same exceptions. A long loop still answers Ctrl-C and lets other threads in. Where the compiler cannot prove a shortcut is safe, it does not take it.

That is the line that separates it from the tools people compare it with. Cython and numba are fast mostly in modes that switch Python's rules off: wrapping integers, unchecked bounds, frozen globals. TypedPython keeps the rules and earns the speed by proof: interval analysis removes checks it can show are redundant, objects that never escape are not allocated, and buffers are read without copying. It is also compiled ahead of time, so it runs where a JIT cannot: on iOS, on Android and in GraalVM native images.

Where it is going

  • Free-threaded code by construction. Because the compiler knows which objects a function owns, it locks only what is shared, using CPython's own critical sections, and declares its modules safe to run without the GIL.
  • Parallel loops. Loops whose iterations are proven independent run across cores on free-threaded CPython.
  • Virtual objects. Short-lived objects in a hot loop are never materialised unless something could observe them.
  • The replacement for C extensions. The reason people write C for Python is speed. Typed Python that compiles safely, on every platform, makes that unnecessary for most code.

무엇인가

TypedPython은 python-multiplatform 안에 있고 두 가지 일을 합니다. 첫째, 빌드 안의 건전성 검사입니다. 프로젝트의 Python을 타입 검사하고, 타입이 Any로 새는 값은 경고가 아니라 오류입니다. 둘째, 선택적 컴파일입니다. 타입 붙은 함수를 중간 표현으로 낮추고, C로 컴파일하고, 앱 안의 평범한 CPython 확장 모듈로 배포합니다.

새 문법도, 새 언어도 없습니다. 함수 하나씩, 컴파일되거나 인터프리터에 남거나 둘 중 하나입니다.

약속: 같은 답, 훨씬 빠르게

컴파일된 코드는 CPython과 정확히 똑같이 동작해야 합니다. 넘친 정수는 한 바퀴 돌지 않고 큰 정수가 됩니다. 인덱스 오류는 같은 예외를 냅니다. 긴 루프도 Ctrl-C에 응답하고 다른 스레드에 차례를 줍니다. 컴파일러가 지름길이 안전하다고 증명하지 못하면 그 길로 가지 않습니다.

흔히 비교하는 도구들과 갈리는 지점이 여기입니다. Cython과 numba가 빠른 것은 대부분 Python의 규칙을 끄는 모드에서입니다. 정수가 한 바퀴 돌고, 경계를 검사하지 않고, 전역 변수를 얼려 둡니다. TypedPython은 규칙을 지키고 속도는 증명으로 얻습니다. 구간 분석으로 필요 없음을 보인 검사를 없애고, 밖으로 나가지 않는 객체는 만들지 않고, 버퍼는 복사 없이 읽습니다. 또 미리 컴파일하기 때문에 JIT가 갈 수 없는 곳, iOS, Android, GraalVM 네이티브 이미지에서 돕니다.

어디로 가는가

  • 처음부터 free-threaded에 안전한 코드. 컴파일러는 함수가 어떤 객체를 소유하는지 알기 때문에, 공유되는 것만 CPython 자신의 critical section으로 잠그고, 모듈이 GIL 없이 돌아도 안전하다고 선언합니다.
  • 병렬 루프. 반복이 서로 독립이라고 증명된 루프는 free-threaded CPython에서 여러 코어로 나뉘어 돕니다.
  • 가상 객체. 뜨거운 루프 안의 짧게 사는 객체는, 무언가 그것을 관측할 수 있을 때만 실제로 만듭니다.
  • C 확장의 대체. 사람들이 Python을 위해 C를 쓰는 이유는 속도입니다. 모든 플랫폼에서 안전하게 컴파일되는 타입 붙은 Python이 있으면 대부분의 코드에서 그럴 필요가 없어집니다.
