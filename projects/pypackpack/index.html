Build and ship

pypackpack

Build once for every platform: the Python half of an app, resolved and compiled for each target. Command: ppp.한 번 빌드해 모든 플랫폼으로: 앱의 Python 절반을 타깃마다 해석하고 컴파일합니다. 명령은 ppp입니다.

GitHub · Guide · PyPI

What it is

An app's Python code has dependencies, and on a phone those dependencies have to be built for that phone. pypackpack, the ppp command, does that for every target at once: it pins and fetches a verified Python, resolves dependencies separately for Android, iOS, desktop and the web (including wheels built for mobile), compiles C and C++ extensions, and bundles the result as resources an app can carry.

It is built on uv for resolution and compiles to a native executable with GraalVM, so it installs as one command with no Java needed.

Build levels

A package can ship at four levels: instant (source), bytecode, native (compiled extensions) and mixed. ppp build checks dependencies, compiles and bundles in one step, and deploys by kind: libraries go to PyPI, apps go to FastTrack, the fast path for shipping code updates to apps.

Where it is going

  • A Cargo backend. Rust crates built as Python extension modules for every target, so Rust is a first-class way to make Python fast in an app. torchnative is the first package that will build this way.
  • TypedPython's output as a build level. Compiled modules from TypedPython shipped through the native and mixed levels.
  • Free-threaded and the web. CPython 3.15t and its stable ABI for free-threaded builds (abi3t) as the baseline, with WebAssembly in the first release; dependencies that would turn the GIL back on are reported at build time.

무엇인가

앱의 Python 코드에는 의존성이 있고, 휴대폰에서는 그 의존성을 그 휴대폰용으로 빌드해야 합니다. ppp 명령인 pypackpack이 그 일을 모든 타깃에 한꺼번에 합니다. 검증된 Python을 고정해 가져오고, Android, iOS, 데스크톱, 웹마다 따로 의존성을 해석하고(모바일용으로 빌드한 휠 포함), C와 C++ 확장을 컴파일하고, 결과를 앱이 품을 수 있는 리소스로 묶습니다.

해석은 uv 위에서 하고, GraalVM으로 네이티브 실행 파일이 되어서 Java 없이 명령 하나로 설치됩니다.

빌드 레벨

패키지는 네 레벨로 배포할 수 있습니다. instant(소스), bytecode, native(컴파일된 확장), mixed입니다. ppp build가 의존성 확인, 컴파일, 번들을 한 단계로 하고, 종류에 따라 배포합니다. 라이브러리는 PyPI로, 앱은 앱에 코드 업데이트를 빠르게 보내는 경로인 FastTrack으로 갑니다.

어디로 가는가

  • Cargo 백엔드. Rust 크레이트를 모든 타깃용 Python 확장 모듈로 빌드합니다. 앱에서 Python을 빠르게 만드는 일급 방법이 Rust가 됩니다. torchnative가 이 방식으로 빌드될 첫 패키지입니다.
  • TypedPython 출력을 빌드 레벨로. TypedPython이 컴파일한 모듈을 native와 mixed 레벨로 배포합니다.
  • free-threaded와 웹. CPython 3.15t와 free-threaded 빌드용 안정 ABI(abi3t)가 기준이고, WebAssembly는 첫 릴리스에 들어갑니다. GIL을 다시 켜는 의존성은 빌드할 때 알려 줍니다.
