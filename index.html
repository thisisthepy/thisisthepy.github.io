A Python that runs everywhere Kotlin runs.Kotlin이 도는 모든 곳에서 도는 Python.

Native apps, on-device AI and interactive graphics, written in Python, shipped to Android, iOS, desktop and the web. Not through a web view and not through a second runtime bolted on the side: CPython embedded in Kotlin Multiplatform, talking to Kotlin in both directions, built by one toolchain.네이티브 앱, 온디바이스 AI, 인터랙티브 그래픽스를 Python으로 쓰고 Android, iOS, 데스크톱, 웹에 배포합니다. 웹뷰도 아니고 옆에 따로 붙인 런타임도 아닙니다. Kotlin Multiplatform 안에 CPython을 넣고, Kotlin과 양방향으로 대화하게 하고, 하나의 도구 체인으로 빌드합니다.

Why this exists왜 만드는가

Python is where most people learn to program, where data and AI work happens, and where notebooks let you change a running program one cell at a time. It is also the language that cannot ship an app. A Python programmer who wants a phone app is told to learn Kotlin or Swift first, and a model that runs in a notebook has to be rewritten before it can run on a device.

Kotlin Multiplatform solved the other half of the problem: one codebase, real native UI through Compose Multiplatform, on every platform that matters. thisisthepy joins the two. The bet is simple: if Python can call every Kotlin library under its own name, and Kotlin can call Python back, then the whole Kotlin ecosystem becomes Python's standard library for apps, and Python becomes a first-class language for building them.

From there the ambitions grow. Python that is as fast as compiled code when you add types. Python that runs on every core, because the interpreter we ship is becoming free-threaded everywhere. Python that drives a 3D scene an AI agent can read and edit. All of it on the device in your hand.

Python은 많은 사람이 처음 프로그래밍을 배우는 언어이고, 데이터와 AI 작업이 이루어지는 언어이며, 노트북에서 셀 하나씩 실행 중인 프로그램을 바꿀 수 있는 언어입니다. 그런데 앱을 배포하지는 못합니다. 휴대폰 앱을 만들고 싶은 Python 개발자는 먼저 Kotlin이나 Swift를 배우라는 말을 듣고, 노트북에서 돌던 모델은 기기에서 돌리려면 다시 작성해야 합니다.

Kotlin Multiplatform은 반대쪽 절반을 풀었습니다. 코드베이스 하나로, Compose Multiplatform의 진짜 네이티브 UI로, 중요한 모든 플랫폼에 배포합니다. thisisthepy는 이 둘을 잇습니다. 내기는 단순합니다. Python이 모든 Kotlin 라이브러리를 원래 이름 그대로 부를 수 있고 Kotlin이 Python을 다시 부를 수 있다면, Kotlin 생태계 전체가 Python의 앱 표준 라이브러리가 되고, Python은 앱을 만드는 일급 언어가 됩니다.

거기서 목표가 커집니다. 타입을 붙이면 컴파일된 코드만큼 빠른 Python. 모든 코어를 쓰는 Python. 우리가 배포하는 인터프리터를 모든 곳에서 free-threaded로 바꾸고 있습니다. AI 에이전트가 읽고 고칠 수 있는 3D 장면을 움직이는 Python. 이 모든 것이 손에 든 기기 위에서 돕니다.

Read it from the bottom. CPython is the interpreter, unmodified, in its free-threaded build. Kotlin Multiplatform and Compose Multiplatform give every platform a native host and a native UI. python-multiplatform embeds the interpreter in that host and builds the bridge: Kotlin calls Python through the C API, Python calls Kotlin through a function table generated at build time. pypackpack resolves and builds the Python half of an app for each target, and toolchain puts it inside the Kotlin build, so a python { } block in Gradle is all an app needs.

On top of that bridge sit the pythonx packages, Python language extensions in the spirit of androidx and kotlinx. They import Kotlin libraries under their own names and make them feel like Python: Compose as decorated functions, coroutines as structured scopes, a 3D renderer as a declarative scene. They all install into one shared pythonx namespace package, so an app picks the ones it needs and they sit side by side. TypedPython compiles the parts that must be fast, and torchnative brings PyTorch-style models to devices that have no PyTorch.

아래에서부터 읽으면 됩니다. CPython은 고치지 않은 원래 인터프리터이고, free-threaded 빌드입니다. Kotlin Multiplatform과 Compose Multiplatform이 모든 플랫폼에 네이티브 호스트와 네이티브 UI를 줍니다. python-multiplatform이 그 호스트 안에 인터프리터를 넣고 다리를 놓습니다. Kotlin은 C API로 Python을 부르고, Python은 빌드 시점에 생성한 함수 표로 Kotlin을 부릅니다. pypackpack은 앱의 Python 절반을 타깃마다 해석하고 빌드하며, toolchain은 그것을 Kotlin 빌드 안에 넣습니다. 그래서 앱에 필요한 것은 Gradle의 python { } 블록 하나입니다.

그 다리 위에 pythonx 패키지들이 있습니다. androidx, kotlinx와 같은 정신의 Python 언어 확장입니다. Kotlin 라이브러리를 원래 이름 그대로 가져와 Python답게 만듭니다. Compose는 데코레이터 붙은 함수로, 코루틴은 구조적 스코프로, 3D 렌더러는 선언형 장면으로. 모두 하나의 pythonx 네임스페이스 패키지에 설치되어서, 앱은 필요한 것만 골라 나란히 씁니다. 빨라야 하는 부분은 TypedPython이 컴파일하고, torchnative는 PyTorch가 없는 기기에 PyTorch 방식의 모델을 가져갑니다.

Apps

One app, end to end앱 하나가 만들어지는 길

A notebook cell declares a screen:

from pythonx.compose.runtime import Composable, app, remember_saveable
from pythonx.compose.material3 import Text, Button

@app
@Composable
def App():
    App.messages = messages = remember_saveable("Hello from Python")
    Text(messages.getValue())

The next cell writes main.App.messages.setValue("changed") and the running window changes within a frame. Redeclaring App replaces the screen; there is no update call. Text is Compose's own Text, reached through python-multiplatform's binder under its Kotlin name; its parameters are also reachable in snake_case. The state is Compose's rememberSaveable, so it survives rotation and process death on Android like any Kotlin app's state.

The same module ships: pypackpack bundles it for each target, the toolchain plugin puts it into the APK, the iOS app and the desktop jar, and the embedded CPython runs it. Nothing in the app had to be written in Kotlin.

노트북 셀 하나가 화면을 선언합니다.

from pythonx.compose.runtime import Composable, app, remember_saveable
from pythonx.compose.material3 import Text, Button

@app
@Composable
def App():
    App.messages = messages = remember_saveable("Hello from Python")
    Text(messages.getValue())

다음 셀에서 main.App.messages.setValue("changed")를 쓰면 실행 중인 창이 한 프레임 안에 바뀝니다. App을 다시 선언하면 화면이 바뀌고, 업데이트 함수는 없습니다. Text는 Compose의 진짜 Text이고, python-multiplatform의 바인더가 Kotlin 이름 그대로 내보내며 인자는 snake_case로도 받습니다. 상태는 Compose의 rememberSaveable이라서, Kotlin 앱의 상태처럼 Android에서 화면 회전과 프로세스 종료 뒤에도 살아남습니다.

같은 모듈이 그대로 배포됩니다. pypackpack이 타깃마다 묶고, toolchain 플러그인이 APK, iOS 앱, 데스크톱 jar에 넣고, 안에 들어간 CPython이 실행합니다. 앱에서 Kotlin으로 써야 했던 코드는 없습니다.

Principles we hold to지키는 원칙

  • The original names, always. A Kotlin name in Python means the original Kotlin. androidx.compose is androidx; nothing is renamed to look Pythonic. What changes is spelling inside a module: members and keywords are also reachable in snake_case.
  • Built at build time, not discovered at run time. Python reaches Kotlin through a table generated by KSP and by an artifact walker that reads compiled jars and klibs. No reflection, no name lookup, so the same app works in a GraalVM native image and on Kotlin/Native.
  • CPython, not a Python-like language. Every extension, every wheel and every semantic rule of CPython applies. When we compile Python, the result must behave exactly as CPython would.
  • Free-threaded, and only free-threaded. The interpreter moves to CPython 3.15t, with no GIL, on every platform including the web; there will be no GIL build. Parallelism comes from threads, not from sub-interpreters.
  • Declarative over imperative. Screens are declared, scenes are declared, motion is declared. Redeclaring is how things change.
  • Tests that can fail. Every claim is backed by a test that was seen failing first, and by pixels where pixels are the claim.
  • 원래 이름 그대로. Python에서 보이는 Kotlin 이름은 원래 Kotlin을 뜻합니다. androidx.compose는 androidx이고, Python처럼 보이게 하려고 이름을 바꾸지 않습니다. 바뀌는 것은 모듈 안의 표기뿐입니다. 멤버와 키워드 인자는 snake_case로도 부를 수 있습니다.
  • 실행 중에 찾지 않고 빌드할 때 만든다. Python은 KSP와, 컴파일된 jar와 klib을 읽는 아티팩트 워커가 생성한 표를 통해 Kotlin에 닿습니다. 리플렉션도 이름 검색도 없어서, 같은 앱이 GraalVM 네이티브 이미지와 Kotlin/Native에서 그대로 돕니다.
  • Python 비슷한 언어가 아니라 CPython. CPython의 모든 확장, 모든 휠, 모든 의미 규칙이 그대로 적용됩니다. Python을 컴파일할 때도 결과는 CPython과 똑같이 동작해야 합니다.
  • free-threaded, 그것만. 인터프리터를 웹을 포함한 모든 플랫폼에서 GIL 없는 CPython 3.15t로 옮기고 있고, GIL 빌드는 두지 않습니다. 병렬성은 서브 인터프리터가 아니라 스레드에서 옵니다.
  • 명령형보다 선언형. 화면도, 장면도, 움직임도 선언합니다. 바꾸고 싶으면 다시 선언합니다.
  • 실패할 수 있는 테스트. 모든 주장은 먼저 실패하는 것을 본 테스트로 뒷받침하고, 화면이 주장이면 픽셀로 증명합니다.

Where it is going어디로 가는가

Fast Python without a new language새 언어 없이 빠른 Python

TypedPython compiles ordinary typed Python ahead of time into extensions that run on phones and in native images, with CPython's exact semantics: big integers, bounds checks, exceptions, signals. Already at Rust's speed on fannkuch.TypedPython은 평범한 타입 붙은 Python을 미리 컴파일해 휴대폰과 네이티브 이미지에서 도는 확장으로 만듭니다. 큰 정수, 경계 검사, 예외, 시그널까지 CPython과 똑같은 의미를 지킵니다. fannkuch에서는 이미 Rust와 같은 속도입니다.

Every core, on every device모든 기기의 모든 코어

Free-threaded CPython everywhere, built by us for Android, iOS and the browser, with compiled code that declares itself thread-safe and parallelises independent loops.Android, iOS, 브라우저용으로 직접 빌드한 free-threaded CPython을 모든 곳에 씁니다. 컴파일된 코드는 스스로 스레드 안전을 선언하고, 서로 독립적인 루프를 병렬로 돌립니다.

Graphics an agent can work on에이전트가 다룰 수 있는 그래픽스
